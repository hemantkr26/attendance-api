# REVIEW.md

Defects found in the starter `app/main.py`. All are fixed in the submitted file.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Minutes are floored *before* the grace check (`minutes > 10`), so 09:40:01 gives 0 instead of 10 (R2 needs "strictly more than 10:00"). | Shift 09:30, punch 09:40:01 -> expected 10, got 0. | Compare whole **seconds** (`> 600`), then `seconds // 60`. |
| 2 | `compute_late_minutes` | Uses the punch's own (naive, server-local) date and clock; no IST conversion; ignores overnight shifts and sub-second values. | Run on a UTC server: a 10:05 IST punch is "04:35" and is compared with 09:30 -> nonsense. | Punch-in is converted to IST; the shift start is built on the *attendance date* (R1) in IST. |
| 3 | `compute_work_hours` | `round(x, 2)` is float/banker's rounding, not half-up (R4). | 18 s of work = 0.005 h -> `round` gives 0.0, spec says 0.01. | `Decimal(seconds)/3600` quantized with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | No 30-minute minimum (R3); shift end for overnight shifts is not on the next day; mixes aware `end` with naive `punch_out` (TypeError); also never called by any endpoint. | 10 min after shift end returns 10 not 0; 22:00-06:00 shift gives a huge negative/zero value. | Rewritten: shift end built in IST on the attendance date (+1 day if overnight), floor minutes, `>= 30` else 0. |
| 5 | `punch_in` | Unknown `emp_code` -> `emp` is `None` -> `TypeError` -> **500**. | POST with `emp_code: "NOPE"`. | 404 via `employee_or_404`. |
| 6 | `punch_in` | Check-then-insert race: two simultaneous requests both pass `find_one` and insert, giving two records. No unique index existed. | Fire 10 parallel identical requests. | Unique index on (`emp_code`,`date`); `insert_one` + catch `DuplicateKeyError` -> 409. |
| 7 | `punch_in` | `datetime.fromtimestamp(ms/1000)` is naive server-local time (not UTC, not IST); `date` is therefore the server's date, not R1's IST date; milliseconds are not truncated; `punched_at=0` is falsy and silently becomes "now". | Server in UTC, punch at 23:30 IST -> wrong `date`. | `from_ms` (UTC-aware, truncated to seconds); `attendance_date()` implements R1 including overnight shifts; `is None` check. |
| 8 | `PunchInIn` | `punched_at` accepts anything numeric (seconds, floats, negatives) and `status` accepts any string including ABSENT/LEAVE. | `punched_at: 1783312500` (seconds) or `status: "ABSENT"` returns 201. | Strict int in [1e11, 4.1e12] ms; `status` limited to PRESENT/WFH/ON_DUTY -> 422. |
| 9 | `punch_in` response | Returns raw `datetime`s (ISO strings, not epoch ms) and an `id` (ObjectId string); the contract has no id. | Compare the response with openapi.yaml. | `serialize_record` returns epoch ms and no id. |
| 10 | `create_employee` | Check-then-insert race on `emp_code` (needs a DB unique index). | Parallel duplicate creates both get 201. | Unique index; 409 on `DuplicateKeyError`. |
| 11 | `create_employee` / `EmployeeIn` | No validation: emp_code format, email, `HH:MM`, a real `joined_on`, `shift_start != shift_end`; `created_at` is naive local `datetime.now()` and returned as ISO. | `shift_start == shift_end`, `joined_on: "2026-02-30"`. | Pydantic patterns/validators; `created_at` stored as UTC and returned as epoch ms. |
| 12 | `list_employees` | `skip = page * page_size` (page 1 skips the first page); `total` counts the whole collection, ignoring the filter; no sort; `page`/`page_size` unvalidated (`page_size=0` or negative -> server error). | `?department=Sales` shows `total` of all employees; page 1 starts at employee 21. | `(page-1)*page_size`; `count_documents(q)`; sort by `emp_code`; `page>=1`, `1<=page_size<=100`. |
| 13 | `list_attendance` | Loads the whole collection into memory and sorts in Python (dies at 100k); sort has no `emp_code` tiebreak; unvalidated dates/status/page; `date_from > date_to` not rejected; returns `_id` as `id` and raw datetimes; legacy records lack `half_day`/`history`. | 100k records: slow and memory heavy; `?date_from=2026-07-09&date_to=2026-07-01`. | Server-side `find().sort().skip().limit()` with a hinted index; validation; `serialize_record` fills defaults. |
| 14 | `/health` | Always returns ok even when MongoDB is down (spec: 503). | Stop MongoDB, call `/health`. | Pings MongoDB; 503 on failure. |
| 15 | `MongoClient(...)` | PyMongo returns naive datetimes; they were then treated as local time. | Instants shift by the server's UTC offset. | `tz_aware=True`; all conversions go through `to_ms`/`from_ms`. |
| 16 | whole file | No indexes at all; endpoints listed in the TODO block were missing. | `explain` shows COLLSCAN. | Indexes created idempotently at startup; all endpoints implemented. |

**Looked at and judged fine:** `load_dotenv()` (its default `override=False` already lets real environment variables win); the `201` status codes on the two POSTs; `409` on a duplicate; the string comparison on `date` for ranges (`YYYY-MM-DD` sorts lexicographically); `doc.pop("_id")` after `insert_one` (correct, but fragile, so I serialize explicitly instead).
